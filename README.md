# 타고난 우리 사이

부모와 자녀의 생년월일시를 작은 이해의 힌트로 바꾸는 모바일 우선 사주·케미 웹서비스입니다. **정보 입력 → 분석 연출 → 궁합 결과 → 상세 이야기 → 공유**까지 브라우저에서 동작합니다.

React + TypeScript + Vite + Tailwind CSS. 서버, DB, API 키 없이 Cloudflare Pages에 배포할 수 있습니다.

> 본 서비스의 사주·궁합 결과는 재미와 참고를 위한 콘텐츠이며, 부모와 자녀의 실제 관계를 판단하는 기준이 아닙니다. 점수는 과학적으로 검증된 관계 진단이나 통계적 확률이 아닙니다.

## 1. 구현한 기능과 화면 설계

### 경험 설계

- **첫 화면:** 핵심 질문, 짧은 소개, 직접 그린 부모·아이 SVG, `우리 궁합 보기` CTA. 크림색 종이와 먹색·다크그린에 소량의 황금색·테라코타를 사용했습니다.
- **2단계 입력:** 부모 → 아이 순서로 관계, 공개용 이름/별명, 양력·음력, 생년월일, 시간 입력. 시간 모름과 음력 윤달을 지원합니다. 이전 단계로 돌아가도 입력이 유지됩니다.
- **검증:** 1~~12자 별명, 연월일 형식, 실제 존재하는 날짜, 윤달 유효성, 00:00~~23:59 시간, 한국 날짜 기준 미래 출생일을 검증합니다. 생년은 1900~2100 범위이지만 미래 날짜는 허용하지 않습니다.
- **분석 연출:** 실제 계산 완료 후 2.8초 동안 세 문구를 순차적으로 보여줍니다. 취소·홈 이동 시 타이머를 정리합니다.
- **결과 Hero:** 별명, 띠·가족 관계, 큰 케미 점수와 카운트업, 관계 타입, 요약 문구를 인연록 형태로 표시합니다.
- **결과 상세:** 일간 오행 요약 → 성격·대화·생활 리듬·감정 회복력·성장 시너지 → 잘 맞을 때 → 부딪히는 이유 → 부모 대화 팁 → 아이의 바람 → 공유용 한 줄.
- **공유:** Web Share API 우선, 미지원·실패 시 클립보드 복사, 클립보드도 차단되면 선택 가능한 링크를 표시합니다. 공유 취소는 오류로 취급하지 않습니다.
- **새 결과 만들기:** 이전 출생 정보와 결과를 비우고 처음부터 시작합니다.
- **접근성:** 입력 레이블, 키보드 포커스, 오류·분석·복사 상태 알림, 점수 meter 의미, 모션 줄이기 설정, safe-area 여백을 지원합니다.

### 디자인과 기술 선택

콘텐츠 폭은 최대 **480px**이고 데스크톱에서도 중앙에 배치됩니다. 동일한 흰색 카드만 반복하지 않고 녹색 Hero, 종이색 지표 카드, 녹회색 이야기, 따뜻한 베이지색 갈등 카드, 편지와 인용문을 섞었습니다. Noto Serif KR / Noto Sans KR 가변 폰트는 자체 호스팅하고, 필요한 유니코드 구간의 WOFF2만 브라우저가 요청합니다.

Tailwind v4의 Vite 플러그인, `@theme`, `@apply`와 별도의 디자인 CSS를 사용합니다. 라우터·전역 상태관리·차트·애니메이션 라이브러리 없이 React 상태, CSS, IntersectionObserver와 requestAnimationFrame으로 구현했습니다. 일러스트와 문양은 직접 작성한 SVG입니다.

참고 URL `https://doryeong.app/n/93takrb2`는 작업 환경에서 접근 오류가 발생해 실제 화면을 열람하지 못했습니다. 요청에 명시된 모바일 구성·간단한 입력·몰입형 결과·카드·공유 원칙을 참고했으며 해당 사이트의 소스, 로고, 문구, 이미지, 캐릭터는 사용하지 않았습니다.


`InputPage`가 사라지면 출생 입력을 보관하던 상태도 제거됩니다. 출생 정보는 localStorage, sessionStorage, 쿠키, 서버, 분석 도구 등에 저장하지 않습니다. 단, 실제 메모리 회수 시점은 브라우저가 관리하며 강제 보안 삭제를 보장하는 기능은 아닙니다.

## 3. 사주와 궁합 계산 방식

### 사주 원국

임의의 연월일 공식 대신 **manseryeok 2.0.0을 고정**해 사용합니다. [`calculateFourPillars`와 오행·음력 변환 API](https://github.com/yhj1024/manseryeok)를 호출하여 연주·월주·일주·시주, 천간·지지와 오행을 얻습니다.

- 양력·음력 및 윤달 입력을 라이브러리에 전달합니다.
- 한국 표준시 KST, 진태양시 보정 없음, `dayBoundary: 'midnight'`를 명시합니다.
- 연주와 띠는 단순 출생연도 나머지 연산이 아닌 **입춘 절입 기준**, 월주는 절기 기준입니다.
- 오행 구성은 사용 가능한 각 기둥의 천간 1개와 지지 1개를 같은 비중으로 셉니다. 지장간·계절 세력·용신 분석은 하지 않습니다.
- **시간 미상:** API에 필요한 시각은 정오로 넣어 연·월·일을 산출하지만, 반환 데이터에서 시주를 제거하고 오행도 6개만 셉니다. 해당 시주를 점수에 사용하지 않습니다.
- 시간 미상일 때 같은 날짜 00:00과 23:59의 연·월주가 다르면 절기 경계 불확실성을 표시합니다. 실제 시간이 알려지면 띠 또는 월주가 달라질 수 있습니다.

### 궁합 규칙 (콘텐츠 모델 v1)

이 가중치는 전통 개념을 가족 관계 콘텐츠로 표현하기 위한 **서비스 자체의 설명 가능한 규칙**입니다. 정통 궁합의 유일한 공식이나 검증된 진단이라고 주장하지 않습니다. 난수·이름 해시·현재 시각으로 점수를 바꾸지 않습니다. 같은 유효한 출생 정보와 같은 엔진 버전은 항상 같은 수치와 문구를 만듭니다. 이름과 가족 관계는 표시 문구에만 반영됩니다.

**지지 쌍의 친화도**는 아래 값을 합하고 `[-1, 1]`로 제한합니다. 같은 지지는 기본 `+0.15`이며 자형이 있다면 함께 반영합니다. 한 쌍에 여러 관계가 있으면 모두 반영합니다.

| 요소 |                            값 | 적용                                                      |
| ---- | ----------------------------: | --------------------------------------------------------- |
| 육합 |                         +1.00 | 자축, 인해, 묘술, 진유, 사신, 오미                        |
| 충   |                         -1.00 | 자오, 축미, 인신, 묘유, 진술, 사해                        |
| 형   |                         -0.55 | 자묘, 인사·사신·신인, 축술·술미·미축, 진진·오오·유유·해해 |
| 파   |                         -0.35 | 자유, 축진, 인해, 묘오, 사신, 미술                        |
| 해   |                         -0.45 | 자미, 축오, 인사, 묘진, 신해, 유술                        |
| 삼합 | 전체 평균에 +0.15 / 완성 그룹 | 신자진, 해묘미, 인오술, 사유축                            |

형은 이 모델에서 방향을 구분하지 않는 쌍 규칙으로 단순화했습니다. 삼합은 두 사람의 사용 가능한 지지를 합쳐 **서로 다른 세 지지가 모두** 존재하고 양쪽에 해당 그룹의 지지가 있을 때만 인정합니다. 두 글자만 있는 반합은 삼합으로 계산하지 않습니다.

**종합 요소:**

| 기호 | 요소                                              | 비중 |
| ---- | ------------------------------------------------- | ---: |
| A    | 연지 친화도 (띠 관계)                             |  20% |
| B    | 두 사람의 모든 지지 교차 쌍 평균 + 완성 삼합 보정 |  30% |
| C    | 일간 오행: 상생 +1, 동일 +0.45, 상극 -0.45        |  20% |
| D    | 오행 보완성 0~~1을 -1~~1로 변환                   |  20% |
| E    | 시지 친화도, 두 사람 모두 시간을 아는 경우        |  10% |

오행은 목→화→토→금→수 순서의 상생 관계를 사용하며 부모→아이/아이→부모 방향은 동등하게 취급합니다. 보완성은 각 오행에 대해 `상대가 20%보다 부족한 비율`을 `내가 제공하는 비율`로 채울 수 있는 양을 양방향으로 합산하고, `0.8`로 나눈 뒤 최대 1로 제한합니다.

```text
weighted = 0.2A + 0.3B + 0.2C + 0.2(2D - 1) + 0.1E
core = 76 + 20 × weighted / 사용한 비중의 합
```

한 사람이라도 시간이 없으면 E를 완전히 빼고 비중의 합 `0.9`로 정규화합니다. B의 교차 쌍 수도 실제 사용한 3~4개 기둥에 맞춰 나눕니다.

**다섯 케미 점수:** 공통 core를 40~50% 사용하면서 서로 다른 요소를 섞습니다. M은 월지 친화도, J는 일지 친화도, T는 완성 삼합 수입니다.

```text
성격 = 0.50 × core + 0.50 × (77 + 12C + 6J)
대화 = 0.50 × core + 0.50 × (76 + 13B + 7C)
생활 = 0.45 × core + 0.55 × (74 + 12M + 10E)  // 미상 E 항 제외
회복 = 0.50 × core + 0.50 × (76 + 13D + 6B)
성장 = 0.40 × core + 0.60 × (79 + 14D + 상극일 때 4 + 3T)
최종 = 0.65 × core + 0.35 × 다섯 케미 점수의 평균
```

각 세부 점수와 최종 점수는 반올림 후 **45~98** 범위로 제한합니다. 관계의 차이를 반드시 감점으로만 표현하지 않도록 성장 점수에도 반영합니다. 실제 가족 관계가 실패할 확률 등으로 읽히는 문구나 근거 없는 전국 상위 퍼센트는 사용하지 않습니다.

### 타입·문구 선택

연지 또는 일지 충 → 불꽃 가족 / 높은 점수 → 찰떡 가족 / 높은 보완성 → 서로 키우는 사이 / 같은 띠 → 닮은 듯 다른 가족 / 나머지는 점수에 따라 든든한 한 팀·밀당 가족으로 분류합니다. 모녀·모자·부녀·부자 표현은 자동 치환합니다.

좋은 순간과 대화 팁은 부모·아이의 일간 오행, 충 또는 오행 관계에 따라 선택합니다. 데이터 파일의 타입·인용문과 오행별 메시지를 추가하고 `compatibility.ts`의 선택 규칙을 조정하면 확장할 수 있습니다.

## 4. 실행 방법

Node.js **24 권장** (`.node-version` 포함, 최소 22.12).

```bash
npm install
npm run dev
```

기본 URL: `http://localhost:5173`. GitHub Codespaces에서는 **Ports → 5173 → Open in Browser**를 선택합니다. 개발 서버는 `0.0.0.0`에 바인딩됩니다.

```bash
npm test              # 계산·공유 단위 테스트
npm run build         # TypeScript 검사 + dist 생성
npm run preview       # 프로덕션 번들 미리보기 (기본 4173)
npm run format:check  # 코드 포맷 검사
```

브라우저 통합 테스트는 처음 한 번 Chromium이 필요합니다.

```bash
npx playwright install --with-deps chromium
npm run test:e2e
```

브라우저 다운로드 위치를 변경한 경우 설치·실행 모두 같은 `PLAYWRIGHT_BROWSERS_PATH`를 설정하세요. 이 작업 환경에서는 `/tmp/saju-browsers`를 사용했습니다. 브라우저 설치는 일반 앱 실행·빌드에는 필요하지 않습니다.

| 5. 입춘 경계           | 양력 1990-06-15 11:30      | 양력 2024-02-04 **17:26 / 17:28** | 17:27 경계, 토끼→용 및 월주 변경         |

`src/data/testCases.ts`에 실제 테스트 데이터를 제공합니다. 단위 테스트는 위 사례 반복 계산, 잘못된 날짜·윤달·시간, 지지 관계, 점수 범위와 변별성, 공유 데이터 출생 정보 제외를 검증합니다. 브라우저 테스트는 전체 사용자 흐름, 실제 타이핑 포커스, 공유·취소·fallback, 손상 링크, 모션 줄이기와 반응형을 확인합니다.

## 5. Cloudflare Pages 배포

Cloudflare의 [Vite 배포 안내](https://developers.cloudflare.com/pages/framework-guides/deploy-a-vite3-project/)와 [빌드 설정 문서](https://developers.cloudflare.com/pages/configuration/build-configuration/)에 맞춘 정적 구조입니다.

Git 저장소 연결 시:

| 설정                      | 값                                              |
| ------------------------- | ----------------------------------------------- |
| 서비스                    | Cloudflare **Pages**                            |
| Framework preset          | React (Vite), 또는 None 후 아래 직접 설정       |
| Root directory            | 저장소 루트 (`/`)                               |
| Build command             | `npm run build`                                 |
| Build output directory    | `dist`                                          |
| Node                      | `.node-version`의 24, 필요 시 `NODE_VERSION=24` |
| API 키 / 런타임 환경 변수 | 없음                                            |
| Functions / Workers / DB  | 불필요                                          |

로컬에서 `npm run build`한 뒤 `dist`를 Pages Direct Upload로 업로드할 수도 있습니다. `dist` 안에 `index.html`, `assets`, `_headers`, favicon과 라이선스가 함께 있어야 합니다.

공유는 루트 URL의 fragment (`/#result=...`)를 사용하므로 별도 `/result` 서버 라우팅이 필요 없습니다. HTTPS 배포에서는 Web Share·Clipboard API가 브라우저 지원 범위 내에서 동작합니다. 미지원 환경은 자동 대체합니다.

`public/_headers`에 CSP, 프레임 삽입 차단, MIME sniffing 차단, `Referrer-Policy: no-referrer`가 포함되어 있습니다. 외부 분석 스크립트와 폰트 CDN은 사용하지 않습니다. 향후 외부 리소스를 추가한다면 CSP와 개인정보 흐름을 함께 검토해야 합니다.

## 6. 공유·개인정보의 경계

- 공유 직전 `sharePayload`가 허용된 키만 새 객체에 복사합니다. 출생 정보와 원국은 객체에 없습니다.
- 포함되는 정보: **공개용 별명, 엄마/아빠·딸/아들 관계, 띠, 일간 오행, 점수·타입·결과 문구와 시간 미상 여부**.
- URL query string은 비우며, 결과는 UTF-8 → Base64URL로 변환해 fragment에 담습니다. fragment는 일반 HTTP 요청의 경로·쿼리에 포함되지 않습니다.
- **Base64는 암호화가 아닙니다.** 링크를 받은 사람, 공유한 앱, 브라우저 방문 기록에서는 별명과 결과를 볼 수 있습니다. UI에 공개 범위를 안내하며 실명 대신 별명을 사용할 수 있습니다.
- 파서는 버전, 길이, 점수 범위, 역할·띠·오행과 문구 타입을 검증합니다. 추가 키는 다시 allowlist로 제거합니다. React의 텍스트 렌더링을 사용하며 HTML을 삽입하지 않습니다.
- 서버 인증·서명이 없으므로 링크 내용의 진위를 보증하지 않습니다. 이를 진단·증명 자료로 사용할 수 없습니다.
- URL 자체가 결과이므로 계정이나 조회 서버 없이 다른 기기에서 같은 결과를 열 수 있습니다.

## 7. 아직 구현하지 않은 부분과 한계

- **실제 Cloudflare 계정 배포·도메인 연결은 하지 않았습니다.** 배포 가능한 빌드와 설정까지 제공합니다.
- **출생지·해외 시간대·진태양시·역사적 서머타임 선택 UI가 없습니다.** KST 입력만을 대상으로 합니다.
- 지장간, 용신·희신, 신강·신약, 대운·세운, 전문가 상담, 실제 관계에 대한 검증된 심리 모델은 구현하지 않았습니다. 형의 쌍 처리와 모든 교차 지지의 동일 비중은 서비스 모델의 단순화입니다.
- 시간 미상인 절기 당일은 정오 기준 잠정 결과입니다. 안내는 하지만 가능한 모든 시각의 결과를 나란히 제공하지는 않습니다.
- 이미지 저장·다운로드, 카카오 전용 SDK, QR 코드, 동적 OG 이미지, 서버 기반 짧은 링크는 없습니다. 소셜 링크 미리보기에는 기본 서비스 정보가 표시되며 개인별 결과는 링크를 연 후 보입니다.
- 결과 텍스트가 URL에 들어가 링크가 길어질 수 있습니다. 일부 메신저의 URL 길이·fragment 처리 제한은 별도 실기기 점검이 필요합니다.
- 서버 저장, 로그인, 결제, 광고·사용자 추적, 분석 대시보드, 관리 콘솔은 없습니다.
- 자동 검증은 Chromium 모바일 에뮬레이션에서 수행했습니다. iOS Safari/Android 실기기의 네이티브 공유 시트와 키보드를 직접 조작한 검증은 하지 않았습니다. native share 호출·취소는 브라우저 테스트에서 stub으로 확인합니다.
- 폰트 전체 빌드 산출물은 여러 WOFF2 구간을 포함합니다. 실제 다운로드는 사용된 문자에 따른 일부 구간이지만, 향후 전송량을 줄이는 폰트 서브셋 최적화 여지가 있습니다.
